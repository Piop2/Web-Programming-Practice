# 웹프로그래밍 중간고사 전 과제: 개인 이력서 만들기 (개인)

## 1. 개요
- 본인의 `smu.ai.kr` 배포 사이트에 개인 이력서를 제작한다.
- 요구사항 정의서와 화면 설계는 아래 내용을 따른다. AI 에이전트 활용은 자유.
- 평가 관점: **요구사항대로 만들었는가? 만든 것을 스스로 검증했는가?**

## 2. 실적의 범위
- 중·고등학교 시절 포함: 동아리, 교내외 대회, 자격증, 봉사, 독학 결과물 등
- 이번 학기 수업 과제도 실적으로 인정
- 반드시 사실에 기반하여 작성

## 3. 개인정보 규칙 (위반 금지)
- 실명, 학번, 생년월일, 주소, 연락처, 얼굴 사진 **기재 금지**
- 출신 학교명 미기재 (예: "○○고 SW동아리" → "고등학교 SW동아리")
- 증빙 캡처에 이름·학교명이 보이면 가릴 것

## 4. 제출
- 기한: 중간고사 전까지 (e-campus)
- `Mid_학번_이름.zip` (소스 파일 + `REPORT.md`) + 배포 URL
- 배포 경로와 파일 구성은 본인이 정함

## 5. 요구사항 정의서
수용 기준은 **모두 충족해야 Pass**.

### F-01 소개
1. 페이지 상단(header)에 활동명이 표시된다 (실명 아님)
2. 소속 "상명대학교 소프트웨어학과 1학년"이 표시된다
3. 관심 분야를 담은 한 줄 소개가 1문장, 50자 이내로 표시된다
4. 창 너비 1280px에서 ①~③이 스크롤 없이 첫 화면에 보인다

### F-02 연락 채널
1. GitHub 프로필 링크가 상단(header) 또는 하단(footer)에 1개 표시된다
2. 클릭하면 본인 GitHub 프로필 페이지로 이동한다
3. 이메일, 전화번호 등 다른 연락처는 페이지 어디에도 없다

### F-03 실적 목록
1. 실적이 4건 이상이며, 1건 이상은 중·고등학교 시절 실적이다
2. 실적마다 시기(YYYY.MM), 분류, 내용, 본인 역할이 모두 표시된다
3. 분류는 프로젝트·수상·자격·활동·교육 중 하나로 표시된다
4. 최신 실적이 위에 오도록 시기 역순으로 정렬된다
5. 실적은 표(table)로 표시된다

### F-04 수강 과목
1. 이번 학기(2026-2) 수강 과목이 모두 목록으로 표시된다
2. 과목마다 과목명과 이수 구분(전공/교양)이 표시된다
3. 「웹프로그래밍 및 AI에이전트 활용」은 F-05 영역으로 이동하는 링크다

### F-05 본 과목 주차별 링크
1. 1~15주차가 모두 표시된다
2. 실습을 진행한 주차는 클릭하면 해당 주차 실습 페이지로 이동한다
3. 진행하지 않은 주차는 "예정"으로 표시되고 링크가 없다
4. 진행한 주차와 예정 주차가 색으로 구분된다

### F-06 최종 수정일
1. 하단(footer)에 "최종 수정일: YYYY-MM-DD" 형식으로 표시된다
2. 표시된 날짜가 배포 저장소의 마지막 커밋 날짜와 같다

### (선택, 가산점) 추가 요구사항 제안
- 이력서에 더 필요하다고 생각하는 요구사항을 직접 정의 → 구현 → 검수
- 위 형식(ID: A-01~, 요구사항, 수용 기준)으로 `REPORT.md`에 작성

## 6. 화면 설계
영역 구성과 **순서**는 아래를 따른다. 색, 폰트, 크기, 세부 배치는 자유. 추가 요구사항 영역은 자유롭게 추가 가능. 영역은 `header`, `section`, `footer`로 구분.

| 순서 | 영역 | 요구사항 | 내용 |
|---|---|---|---|
| 1 | header | F-01, F-02 | 활동명 · 소속 · 한 줄 소개 \| GitHub 링크 |
| 2 | section – 실적 | F-03 | 시기 \| 분류 \| 내용 \| 역할 (표, 최신순) |
| 3 | section – 수강 과목 | F-04 | 과목명 (전공/교양) 목록 |
| 4 | section – 웹프로그래밍 주차별 링크 | F-05 | 1주 2주 … 7주 \| 8주(예정) … 15주(예정) |
| 5 | footer | F-06 | 최종 수정일: YYYY-MM-DD |

## 7. 평가 기준

### Ⅰ. 실행 [70] – 결과물
- **요구사항 구현 [30]**: F-01~F-06 (항목당 5점)
- **HTML – 구조와 의미 [15]** (Q-HTML)
  - 문서 기본 정보 (DOCTYPE, lang, charset, title)
  - 구조 요소로 영역 구분 (header, main, section, footer 등)
  - 내용에 맞는 요소 사용 (표 데이터는 표, 나열은 목록, 이동은 링크, 이미지 대체 텍스트)
  - W3C HTML 검사기 오류 0
- **CSS – 표현과 분리 [15]** (Q-CSS)
  - 모든 표현은 외부 스타일시트로 (인라인 style, 표현용 태그 금지)
  - 색·폰트·여백의 일관성 / 창 크기가 변해도 배치 유지
  - W3C CSS 검사기 오류 0
- **배포 [10]** (Q-DEPLOY): 배포 URL 정상 동작, 깨진 링크·이미지 없음

### Ⅱ. 분석 [30] – `REPORT.md`에 작성
- **인수 검수표 [20]**: F-01~F-06, Q-HTML, Q-CSS, Q-DEPLOY 전체를 검수
  - Fail을 정직하게 적은 것은 감점 없음

  - 완성도 = 충족한 요구사항 수 ÷ 평가 대상 요구사항 수 (9개)

  - 다음 프로젝트에서 무엇을 다르게 할 것인가
